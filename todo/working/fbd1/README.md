# FBD1 Design Construction

## What this model does

This MiniZinc model builds an **FBD1 design** by choosing a sequence of integer values that must interact in a very controlled way. The model is looking for a compact design in which many derived values—such as pairwise sums, pairwise differences, and doubled values—are all distinct.

At a high level, this is a **combinatorial design** problem: we want a small set of numbers that creates a rich structure without accidental clashes between the important quantities derived from them.

## Input

The model takes one main input:

- `k`: the number of main factors in the design.

For example, the supplied instance files simply set `k` to values such as 4, 6, 7, 8, or 9.

## Decision variables

The model chooses:

- `n[i]` for `i = 1..k`: the main integers that define the design.
- `n_star`: one extra integer used to complete the construction.

These values are the core of the design. The `n[i]` values are required to be strictly increasing, so the model searches for an ordered sequence rather than arbitrary duplicates or permutations.

## Derived quantities

Several helper arrays are built from the chosen values:

- `Q[i] = 2 * n[i]`: the doubled values.
- `T_plus`: all pairwise sums `n[i] + n[j]` with `i < j`.
- `T_minus`: all pairwise differences `n[j] - n[i]` with `i < j`.
- `Q_folded`: values of the form `2*n[k] + n_star - 2*n[i]`.
- `T_plus_folded`: values of the form `2*n[k] + n_star - (n[i] + n[j])`.

You can think of these as the important “signals” generated by the design. A valid design is one where these signals stay separate from each other.

## Constraints

The model enforces several types of rules:

### 1. Increasing order

The main values must satisfy:

- `n[1] < n[2] < ... < n[k]`

This removes symmetry and ensures the design is built from a clean ordered sequence.

### 2. All important derived values must be different

The model collects all of the following into one large list:

- the original `n[i]` values,
- the pairwise differences,
- the pairwise sums,
- the doubled values,
- the folded sums,
- the folded doubled values.

It then applies an `alldifferent` constraint. This is the heart of the model: it prevents collisions between any two important quantities.

### 3. Simple bounds

The model also imposes basic lower and upper bounds, including:

- each `n[i]` must be at least `i`,
- each doubled value must be at least `2*i`,
- `n_star <= 2*n[k] + 1`.

These bounds keep the search focused on sensible candidate designs.

### 4. Extra exclusion rules

Two additional families of clashes are forbidden explicitly:

- no later design value `n[j]` may equal `2*n[i]`,
- no later design value `n[j]` may equal `3*n[i]`,

for `i < j`.

These rules strengthen the design by ruling out patterns that would make the structure less distinct.

## Objective

The model minimizes:

- `N = 2*n[k] + n_star`

This means it tries to find the **smallest possible overall design size** that still satisfies all constraints. In other words, among all valid designs, it prefers the most compact one.

## How to read the solution

A solution gives:

- the selected ordered values `n`,
- the extra value `n_star`,
- the resulting size `N`.

The output arrays such as `Q`, `T_plus`, and `T_minus` are also useful because they show the structure created by the chosen design and help confirm that the important quantities are all distinct.

## Notes and uncertainty

From the model alone, it is clear that this is an optimization problem about constructing a special integer design with strong uniqueness properties. However, the exact expansion of the acronym **FBD1** and the original application domain are **not stated in the model file**, so that part should be checked by someone with domain knowledge or by consulting the original source of the benchmark.
