# Large Cumulative Scheduling

## Problem Description

This model solves a **resource-constrained scheduling problem**: given a set of tasks that each consume some amount of a shared resource, schedule all tasks so that the resource is never overloaded and the total schedule length (makespan) is as short as possible.

Think of it like a factory with a single machine (or workforce) of limited capacity. Each job takes a certain amount of time and requires a certain share of that capacity while it runs. The challenge is to decide when each job should start so that at no point in time is the total demand on the machine greater than its capacity, and all jobs finish as early as possible.

This benchmark was specifically designed to test the **scalability** of constraint propagation algorithms for the `cumulative` global constraint when there are many tasks with large durations. The instances were randomly generated by Pierre Schaus and used in a paper submitted to the CP 2015 conference.

## Parameters

| Parameter | Description                                                                                                                             |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `capa`    | The total capacity of the shared resource (e.g., maximum number of workers available at any time)                                       |
| `n_tasks` | The number of tasks to be scheduled                                                                                                     |
| `d[i]`    | Duration of task `i` — how long the task takes to complete                                                                              |
| `r[i]`    | Resource demand of task `i` — how much of the shared resource task `i` uses while running                                               |
| `horizon` | An upper bound on the schedule length, computed as the sum of all task durations (the worst case where all tasks run one after another) |

## Variables

| Variable    | Description                                                                                                       |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `s[i]`      | The **start time** of task `i` — the main decision variable; the solver chooses when each task begins             |
| `objective` | The **makespan** — the time at which the last task finishes, equal to the maximum over all tasks of `s[i] + d[i]` |

## Constraints

- **Cumulative constraint**: At every point in time, the total resource demand of all tasks running simultaneously must not exceed `capa`. This is enforced using the MiniZinc `cumulative` global constraint.
- **Redundant constraint**: Every task must finish no later than the makespan (`s[i] + d[i] <= objective`). This constraint is logically implied by the definition of `objective` but is stated explicitly to help the solver prune the search space more effectively.

## Objective

**Minimise** the makespan (`objective`) — that is, find a schedule where all tasks complete as early as possible while respecting the resource capacity limit.

## Instances

The benchmark includes instances ranging from **100 to 3200 tasks**, with durations in the thousands of time units. The naming convention `instance-NNNN-K` indicates approximately `NNNN` tasks and instance variant `K`. These instances appeared in the MiniZinc Challenge in **2015** and **2018**.

## Reference

The instances were created by **Pierre Schaus** for a paper submitted to the **21st International Conference on Principles and Practice of Constraint Programming (CP 2015)**.
