# Waste Water Treatment Plant Scheduling (`wwtpp.mzn`)

## What problem is this model solving?
This MiniZinc model schedules wastewater releases from multiple industries into a shared treatment plant over a fixed number of time steps (here, effectively a 24-step horizon).

Each industry generates wastewater demand `d[i,j]` at time `j`. It can:
- send some flow directly to the plant (`c[i,j]`), and/or
- temporarily store flow in a local buffer tank (`buf[i,j]`) and release later (`bout[i,j]`).

The goal is to find a **feasible schedule** that never overloads the plant and respects each industry’s tank limits and allowed discharge pattern.

## Key inputs (parameters)
- `INDUSTRIES`, `TIMESTEPS`: problem size.
- `max_capacitat`: maximum total plant inflow per time step.
- `d[i,j]`: wastewater generated by industry `i` at time `j`.
- `TankFlow[i]`: max release rate from industry `i`'s buffer.
- `TankCapacity[i]`: max storage volume of industry `i`'s buffer.

## Decision variables
- `c[i,j]` (integer, nonnegative): amount sent directly from industry `i` to plant at time `j`.
- `buf[i,j]` (integer, nonnegative): amount stored in industry `i`'s tank at end of time `j`.
- `bout[i,j]` (integer, nonnegative): amount released from industry `i`'s tank to plant at time `j`.

## Main constraints (beginner view)
1. **Plant capacity per time step**
   - Sum of all direct flows and buffer outflows cannot exceed `max_capacitat`.

2. **Buffer balance over time**
   - At each step, storage evolves by:
     previous storage − released amount + new generated flow − direct discharge.

3. **Start/end behavior**
   - Initial outflow from buffers is forced to zero (`bout[i,1] = 0`).
   - Buffers must be empty at the end (`buf[i,24] = 0`).

4. **Physical buffer limits**
   - `bout[i,j] <= TankFlow[i]` (release-rate limit).
   - `buf[i,j] <= TankCapacity[i]` (tank-size limit).
   - Cannot release more than available stored amount.

5. **On/off style discharge windows for `c[i,j]`**
   - Many explicit constraints force specific time slots to either:
     - be unavailable (`c[i,j] = 0`), or
     - allow an all-or-nothing choice (`c[i,j] = 0` or `c[i,j] = d[i,j]`),
     - sometimes in grouped blocks (multiple consecutive times tied together).
   - This encodes operational availability/forbidden periods for each industry.

## Objective
There is **no optimization objective** in this model.

The solve item is `satisfy`, so the solver only needs to find any schedule that satisfies all constraints.

## Output
The model prints full arrays for:
- `buf` (buffer levels),
- `bout` (buffer releases),
- `c` (direct discharges).

## Uncertainty and assumptions
- The model hard-codes several time-specific constraints (especially for industries 1–8), but the business meaning of each window is not documented in the file. They are interpreted here as operational discharge permissions/restrictions.
- `buf[i,24] = 0` assumes a 24-step horizon endpoint condition. If `TIMESTEPS` differs from 24 in data, that would be inconsistent unless data always uses 24.
- Units (e.g., m³/h, liters/slot) are not stated; interpretation assumes all flow/capacity terms share consistent units.
