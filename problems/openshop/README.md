# Open-Shop Scheduling Problem

## Problem Description

The **Open-Shop Scheduling Problem (OSSP)** is a classic combinatorial optimisation problem in scheduling theory.

There are a number of **jobs** to be processed and a number of **machines** available to process them. Each job consists of exactly one task per machine. Unlike the related [Job-Shop Scheduling Problem](https://en.wikipedia.org/wiki/Job-shop_scheduling), the tasks within a job have **no required ordering** — they may be performed in any sequence. The key constraints are:

- Each machine can work on **at most one task at a time**.
- Each job can have **at most one of its tasks being processed at a time**.
- Tasks **cannot be interrupted** once started.

The goal is to find a schedule — a start time for every task — that **minimises the makespan**: the time at which the last task across all jobs finishes.

## Parameters

| Parameter                 | Description                                                         |
| ------------------------- | ------------------------------------------------------------------- |
| `n_machines`              | The number of machines available.                                   |
| `n_jobs`                  | The number of jobs to be scheduled.                                 |
| `job_task_duration[j, k]` | The duration of task `k` of job `j`. Task `k` requires machine `k`. |

Each job has exactly `n_machines` tasks (one per machine), so `n_tasks_per_job = n_machines`.

## Decision Variables

| Variable               | Description                                                        |
| ---------------------- | ------------------------------------------------------------------ |
| `job_task_start[j, k]` | The start time of task `k` of job `j`.                             |
| `objective`            | The makespan — the earliest time by which all tasks have finished. |

Start times are bounded between `0` and `max_duration` (the sum of all task durations, an obvious upper bound). A tighter lower bound `min_duration` is computed as the maximum of: the total duration of any single job, and the total load on any single machine.

## Constraints

1. **Non-negativity:** All task durations are non-negative and no task starts before time zero.
2. **No overlap within a job:** The tasks belonging to the same job must not overlap in time (since only one task per job can run at a time).
3. **No overlap on a machine:** Tasks assigned to the same machine (i.e., tasks with the same index `k` across all jobs) must not overlap in time.
4. **Makespan bound:** The makespan `objective` must be at least as large as the finish time of every task.

## Objective

Minimise the **makespan** (`objective`) — the time at which the entire schedule completes.

## Benchmark Instances

The model references three sets of well-known benchmark instances:

- **`tai*`** — Generated by E. Taillard. _Benchmarks for basic scheduling problems._ European Journal of Operational Research, 64(2):278–285, 1993.
- **`gp*`** — Generated by C. Guéret and C. Prins. _A new lower bound for the open-shop problem._ Annals of Operations Research, 92:165–183, 1999.
- **`j*per*`** — Generated by P. Brucker, J. Hurink, B. Jurisch, and B. Wöstmann. _A branch & bound algorithm for the open-shop problem._ Discrete Applied Mathematics, 76(1–3):43–59, 1997. These instances are noted in the model as generally the most difficult.

## Notes

This model was adapted from Ralph Becket's `jobshop.mzn` by Diarmuid Grimes. The primary difference from a job-shop model is the absence of any fixed task ordering within a job. The no-overlap constraints are expressed both via a custom `no_overlap` predicate and redundantly using the `cumulative` global constraint, which may help solvers reason more effectively.
